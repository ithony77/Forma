# Design System: Forma Generated Websites and Apps

## Overview

**Creative North Star: "Coordinated Native Worlds"**

Forma’s generated sites and apps are a configurable collection of coordinated worlds. The system enables distinctive reusable native interactions and diverse authored layouts through finite choices. Its twelve style families coordinate palette, heading font, density, radius, scale, width and motion; locks and manual settings can retain or override those defaults. The Drawing Office editor has its own identity and is outside this document.

The common foundation is readable, editable, offline-capable HTML with semantic controls. The catalog contains 105 blocks, 24 reusable elements, 12 styles, 12 palettes and 8 prepared example projects. Each hero or application pattern retains its authored topology; one software example does not establish a universal first viewport. Prepared text, values and artwork are replaceable authored material, never proof of customer outcomes or JEV-generated content.

**Key Characteristics:**

- Twelve selectable coordinated style families, with explicit overrides.
- Native HTML semantics and readable default content.
- Responsive full-width content within page gutters; scrolling scoped to collections.
- Temporary visitor interactions, separate from saved project data.
- Local assets and system fonts; no runtime CDN or remote font dependency.

## Colors

Twelve complete palettes share semantic roles. Frontmatter keys use the actual palette ID followed by its role; no one palette is the generated system’s global brand.

### Primary

The selected palette’s accent supplies primary actions, selection, native range/checkbox accents and focus. Its paired on-accent color supplies readable text on that accent. Palette names are Sand, Forest, Slate, Cobalt, Ink, Lavender, Porcelain, Midnight, Sage, Ocean, Clay and Monochrome. Ink and Midnight are dark palettes.

### Neutral

Background is the page field; surface is the ordinary panel; ink is primary text; muted supports secondary copy; line divides or outlines; soft provides tonal emphasis. Style presets select a palette but manual controls may select any allowed set. CSS variables are scoped to the generated site and may be remapped by a section.

Contrast tone swaps the selected palette’s ink/background pair, derives surface, muted, line and soft with the authored color mixes, and changes accent/on-accent together. Soft tone changes the section background and panel fill. Keep these mapped pairs intact.

**The Coordinated Roles Rule.** Select a palette as one set of foreground, background, accent and boundary roles. Contrast sections remap the full set; do not replace only a background and leave incompatible text or action colors.

## Typography

**Display Font:** selected local Modern sans, Editorial serif or Technical mono stack from the frontmatter.
**Body Font:** local Modern sans stack, including native platform fallbacks.
**Label/Mono Font:** Technical mono headings also appear in Industrial/Technical Mono metadata; numeric data uses tabular figures.

There is no imported font asset. Inter is a preferred installed family name, not a downloaded dependency. Serif and mono selections alter headings while body copy remains sans-serif.

**The Local Type Rule.** Use locally available system stacks. No font download is required or permitted by the product’s installation-free and offline export constraints; these stacks are a binding delivery constraint, not a claim to bespoke display typography.

### Hierarchy

- Base hero display and section headlines use quiet, balanced or dramatic token groups. Centered and editorial base heroes have their own display variants. Heading size does not imply one universal weight: ordinary headings use the authored base weight, Technical mono changes it, and expansion headings use a style-aware weight.
- Expanded heroes retain their own display role and authored variations, including the poster. Their display fallback is independent of the base hero scale tokens; do not promise that every pattern responds identically to the scale selector.
- Body starts from the frontmatter body role. Expanded copy uses a readable maximum measure (70ch), balanced wrapping and preserved line breaks. Section descriptions and hero passages may use their authored larger body treatment.
- Expanded card titles, metadata and controls use the named frontmatter roles. Expanded heading weight defaults to 650; Swiss uses 750, Quiet Luxury 500 and Neo-Brutalist 800.
- Base heroes/headlines use the renderer’s explicit tablet/mobile variants; expansion compositions use their own responsive CSS. There is no single mathematical type ratio across all patterns.

Small uppercase eyebrows present in legacy base blocks are not a reusable prescription in this vocabulary. Use authored metadata for real context; do not invent marketing labels above content.

## Layout

The story through the builder is preview, add and edit blocks/elements, select a coordinated style, open editable examples, and export offline. Generated page composition remains specific to the selected content and block.

Page width choices resolve to focused (920px), standard (1120px), or wide (1360px). Containers use the lesser of the selected width and viewport minus gutters: desktop total gutter (100px), at 1000px and below (64px), and at 700px and below (40px). Mobile content therefore uses the full available content column, with collection overflow scoped inside it.

Section density uses the frontmatter compact, balanced or airy rhythm. Per-section compact/generous factors are authored choices (.65 and 1.4); mobile sections retain a minimum vertical space (24px). Reusable element slots use a responsive auto-fit grid with a bounded minimum (320px) and the expansion gap. Tools appear before block content and content elements after it, within their owning section; up to four elements belong to a selected unlocked content section.

Expanded collections commonly move from three columns to two at 800px and one at 520px. Split introduction/product/project layouts stack at 800px, keep children shrinkable, and preserve content within the column. Native tab lists, logo collections, quotations, milestones and tables may retain local scrolling. Side navigation becomes a fixed desktop rail at 1100px; smaller layouts use the authored horizontal header. Base blocks and original app screens retain their own established responsive breakpoints.

**The Authored Topology Rule.** Keep the chosen block’s composition. Section spacing, alignment, surfaces and media ratios are explicit finite controls; they do not turn every hero, gallery or application into the same grid.

**The Wrapper and Rail Rule.** A section wrapper remains a normal block with its heading above its content. Only the inner collection owns horizontal overflow, motion or snapping; the logo section itself must never become the scrolling rail.

## Elevation & Depth

The shared foundation is flat, with fine boundaries and tonal surfaces. Depth is style-specific: Soft Product uses a diffuse low shadow; Neo-Brutalist uses strong borders and hard offset shadows; Frosted Glass uses an opaque surface first and translucency/blur only under feature support. Dark Studio changes palette and imagery framing without making every panel glow. Device frames, navigation docks and modal panels have functional framing or elevation in their own components.

**The Scoped Expression Rule.** Offset shadows belong to Neo-Brutalist; frosted panels belong to Frosted Glass. Decorative movement is gated by the selected motion mode and reduced-motion preference, never required to read content or operate a control.

Exact shadow and motion values live in the sidecar’s extensions. None is a global requirement. Motion none is the default theme; subtle permits authored hover/feedback transitions; expressive additionally enables bounded entrance, layer or logo movement. Moving logos pause on hover/focus and expose a named pause/resume control. Reduced motion disables decorative animation and transforms; tabs, search, dialogs, sliders and form steps remain usable.

## Shapes

Cards resolve the actual sharp, soft or round radius tokens; buttons have their own corresponding square, softened or pill tokens. Style CSS may intentionally refine those roles: Swiss, Warm Paper, Industrial and Technical Mono use square framing; Botanical arches image corners; Playful Pastel uses asymmetric image corners and pill controls; Gallery Minimal removes framing; Dark Studio uses restrained image corners. These authored silhouettes belong to their style.

The default expansion border is fine (1px), with a stronger Neo-Brutalist border (2px). Section surface controls can select plain, outlined or filled panels; do not apply a universal card treatment to narrative chapters, rails, data tables or image-led work. Uploaded image dimensions and fit remain bounded to their existing slots.

## Components

Native disclosures, tabs, fields and selected states use the active page and section variables. Generated-site interactions are implemented by the fixed local runtime. The private editor-tooling sidecar is excluded from the distributed source.

### Buttons and selection controls

Primary links use accent/on-accent, secondary links use transparent fill and a boundary, and native controls use the selected surface and ink. Primary/secondary action geometry and native-control padding are the frontmatter values. Native controls hover to soft and selected/pressed controls use accent/on-accent. Disabled controls reduce opacity and retain a disabled cursor. Subtle motion may raise authored actions slightly.

All focusable native controls, summaries and links receive the visible accent outline (3px) with offset (4px). Do not substitute hover state for keyboard state.

### Inputs, navigation and disclosures

Search and fields have visible labels, a fine border, surface fill, control radius and a minimum height (44px). Range, checkbox and radio controls use native semantics and accent-color. Search/filter results announce status and preserve a readable empty state. Navigation uses named destinations; the current location receives an underline and accent, with responsive wrapping or locally scrolling dock links.

Native details/summary preserves a readable disclosure without JavaScript. Expanded summaries have a minimum activation height (44px). Enhanced dialogs use native dialog/showModal, Close and Escape, then restore focus to the trigger; lightboxes also offer previous/next and arrow-key navigation. Tabs receive associated tab/panel semantics, roving focus and Arrow/Home/End keyboard navigation only when enhanced.

### Cards, collections and metadata

Expanded cards use the current panel, line, radius and style-scoped depth. Shared padding and gaps come from the frontmatter; small screens reduce card padding. Collections retain their captions and authored text. A logo section contains a normal heading and a separate scrollable logo collection; only that inner collection receives rail styling.

**The Content before Metadata Rule.** In expanded feature cards, show the feature icon, authored title and description, then supporting metadata. Metadata describes the feature; it must not become an invented kicker above the feature copy.

### Visitor state and prepared examples

**The Transient Interaction Rule.** Search, selections, tags, pagination, form values, quantity and task progress change the visitor’s current view only. They never rewrite project data, saved authored values or JEV state.

Default unenhanced markup exposes authored panels and content. Inspect reveals panels and disclosures for editing; Interact restores the visitor’s temporary view state. Local account and order controls demonstrate frontend behavior only. Guided inquiry prepares an email draft through the validated public address.

Eight prepared examples—architecture, software, photography, boutique stay, agency, storefront, analytics and project management—use ordinary editable catalog entries. Additional pages demonstrate all style families; primary pages include all reusable element kinds. People, quotations, logos, values and claims remain prepared drafts. Existing fallback landscape SVG plates are authored local assets colored from the selected palette, predate this expansion, and are not generated imagery.

## Do's and Don'ts

### Do:

- **Do** select a coordinated style, then preserve locked settings and explicit manual overrides.
- **Do** keep collection scrolling inside the section’s content area and allow headings to use the available width.
- **Do** place expanded feature metadata after its title and description.
- **Do** retain native labels, details/summary, table captions and headings, keyboard focus, and readable unenhanced content.
- **Do** suppress decorative effects for reduced motion while keeping functional controls usable.
- **Do** replace prepared people, quotations, logos, statistics, prices and images with verified authored content before publishing.
- **Do** extend the finite catalog, shared validation, renderer, local CSS/runtime and relevant tests together.

### Don't:

- **Don’t** apply the Drawing Office editor identity to generated sites or make a showcase’s composition universal.
- **Don’t** use remote fonts, runtime component downloads, React, Tailwind or CDN requirements for generated primitives.
- **Don’t** put an overflow rail class on a section wrapper or clip the section heading with collection overflow.
- **Don’t** use decorative motion, hidden panels or hover alone as the only route to authored content.
- **Don’t** carry Neo-Brutalist offset shadows into unrelated styles or treat glass transparency as a legibility requirement.
- **Don’t** describe prepared copy, fallback SVG art, local demo rules or manual edits as JEV-generated content.
- **Don’t** imply that local account, order, checkout or billing interfaces supply authentication or payment processing.
